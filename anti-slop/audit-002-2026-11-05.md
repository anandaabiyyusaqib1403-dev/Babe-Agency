# Settings UI Audit 002

Date: 2026-11-05
Scope: `src/app/settings/`, Settings actions, and the global Settings navigation entry. Audit performed after the requested UI implementation. No audit findings have been fixed yet, per the selected AFTER mode.

## Findings

### 1. HIGH — Several Settings sections are informational shells rather than complete workflows

My Profile is read-only; Agency Profile only saves the agency name and regional defaults; Members & Access has no search, filters, invite, role changes, activate/deactivate, or remove actions; Integrations has no connection/test/dashboard actions; Notifications only controls task reminder email; and Security offers reset and sign-out but no password change or session controls. Billing has editable core identity and bank fields, but no logo upload, tax configuration, or invoice preview. Users cannot complete many workflows named in the Settings brief.

**Rule:** C-2 Functional Completeness; R-26 (interactive elements and requested workflows must work). Some gaps map to unavailable schema or unconfigured providers, so the interface should continue to identify those limits clearly.

### 2. HIGH — Save failures do not preserve a recoverable form state

The three server actions throw on validation or database errors. There is no inline action state or error summary to explain the failure while keeping the submitted values visible. A failed network or authorization check therefore leaves the user without the requested Settings error feedback and recovery path.

**Rule:** C-4 Resilience; R-27 (errors must be visible and explain the next step).

### 3. MEDIUM — Query errors can appear as empty/default Settings values

The Settings page does not check errors from the agency, billing, preference, access, and member queries consistently. For example, a billing read error can render empty fields that resemble an unconfigured profile, and an access read error is treated as restricted access without explaining that the lookup failed.

**Rule:** R-27 (loading, empty, and error states must be distinct and perceivable).

### 4. MEDIUM — Settings route has no dedicated loading or section-level empty/error state

The route waits for its Supabase reads without a `loading.tsx`. Several sections render their ordinary content using null fallbacks when configuration is absent; read errors are not consistently separated from legitimate empty settings.

**Rule:** R-27; C-4 Resilience.

### 5. HIGH — Settings route has TypeScript errors

`npx.cmd tsc --noEmit` reports an implicit `any` in the profile initials formatter and a possible null access to `memberResult` in the member table branch (`src/app/settings/page.tsx`). The same check also reports three existing errors in Documents and one in the document upload route. Settings cannot be considered type-checked until its two errors are corrected.

**Rule:** C-2 Functional Completeness (the route must compile and run).

## Existing strengths

- Settings is one link in the existing global sidebar, with internal section navigation and a mobile horizontal scroller.
- The color and type treatments use the established BABE tokens, real form labels, visible focus styling, native controls, and reduced-motion behavior inherited from the app.
- Current invoice snapshots are not edited by the billing save action; the UI states that billing changes apply to new invoices.
- Integration statuses do not expose credentials and explicitly distinguish reminder queue status from email delivery confirmation.
- The members query is capped at 100 rows and shown only to owner/admin users; billing writes verify the caller's role and rely on existing RLS.

## Verification limits

- `npm.cmd run lint` completed successfully.
- `npm.cmd run build` failed in the existing `src/app/api/documents/upload/route.ts:6`: route segment `runtime` is incompatible with the repository's `nextConfig.cacheComponents`. That route is outside Settings and was not changed.
- `npx.cmd tsc --noEmit` reports two errors in the new Settings page plus three existing errors in Documents and one existing error in the document upload route.
- Visual click-through testing was not completed: no development server was running, and an authenticated agency session was not available in this tool session.
- No live Supabase data was modified as part of verification.
