# Workspace UI Audit 001

Date: 2026-11-05
Scope: BABE AGENCY Workspace, Clients and Content Planner. This audit covers the current source and available Supabase schema. No application files or database objects were changed.

## Findings

### 1. HIGH — Client management stops at a partial list and create form

`src/app/clients/page.tsx:12-32` reads only brand name, code, status, and creation time, caps the result at 100, and has no search, status/industry filters, sorting, or pagination. The only create form accepts `brand_name`; `createClientAction` inserts that field alone. There is no edit action or client detail route, and archive is the only row action. This leaves most of the requested Clients workflow unavailable, including contact, package, service period, overview, brief, pillar, and client content.

**Rule:** C-2 Functional Completeness; R-26 (all required controls and flows must work). The existing active-member RLS and matching live schema are present, so the gap is application coverage rather than a missing base client table.

### 2. HIGH — Content Planner does not provide its requested planning views or detail flow

`src/app/content/page.tsx:11-50` loads up to 100 master content rows and 50 publication schedules without URL filters or pagination. It renders a create-and-schedule form, an additional-schedule form, and a schedule table. There is no search/filter bar, table/calendar toggle, calendar, master-content list, content detail route, edit flow, quick workflow status update, or publication schedule edit/cancel action. The current “Mark published” action only moves a schedule to published.

**Rule:** C-2 Functional Completeness; R-26. The schema already separates `contents` from `content_schedules` and supports multiple schedules, but the interface does not expose the full workflow.

### 3. HIGH — Client and content form submissions lack usable validation feedback

The current create and schedule forms submit to server actions in `src/app/actions/operational-actions.ts:31-109`. Invalid values and database failures are thrown as errors, while the pages show no saved-state confirmation or field-level error summary. Users therefore do not get a clear recovery path after a failed submission. Client creation redirects to `?saved=1`, but `src/app/clients/page.tsx` does not read that parameter or render success feedback.

**Rule:** C-2 Functional Completeness; R-27 (errors and state changes need visible, informative feedback).

### 4. HIGH — Workspace pages have no loading state

There is no `src/app/clients/loading.tsx` or `src/app/content/loading.tsx`. Both pages perform uncached server-side Supabase reads before rendering (`clients/page.tsx:9-12`, `content/page.tsx:8-18`), so navigation has no route-level loading feedback while those requests are pending. Empty and error states exist for some results, but do not cover loading.

**Rule:** R-27 (every data view needs an informative loading, empty, and error state).

## Existing strengths

- Sidebar already has only Clients and Content Planner within Workspace; it does not add submenu items for supporting features.
- Existing design tokens use off-white, white, charcoal, muted gray, and forest green, with a visible focus outline and restrained borders.
- Tables have controlled horizontal scrolling on narrow viewports.
- Supabase audit confirmed the relevant existing client/content tables have RLS enabled; the active-member policy model is present. No duplicate tables or migration changes are needed to begin the UI work.

## Verification limits

The live BABE AGENCY project has no client or content records, so create/edit/archive and schedule flows could not be exercised against representative workspace data during this audit. No synthetic production rows were inserted. This is a source/schema audit, not a click-through test.
